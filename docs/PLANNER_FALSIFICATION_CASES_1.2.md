# CORE OS 1.2 — Planner Falsification Cases

The candidate is falsified by any demonstrated case where: a dependency is silently omitted; a cycle produces an executable plan; two identical normalized inputs produce different plans; declared cost can exceed budget; a mandatory provider requirement is unresolved but the plan is accepted; external mutation provider eligibility expands authority; an application-specific identifier changes planner logic; legacy strings cease to be accepted; or the release artifact omits the planner module.

These are failure criteria, not aspirational requirements. Any reproduced case blocks merge eligibility until repaired and requalified.
